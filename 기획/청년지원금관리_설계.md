# 청년지원금 관리 (10차) 설계

## 왜
청년일자리도약장려금(25년 잡모아 → 26년 메이크인이 관리기관)은 청년을 채용하면 6개월·9개월·12개월·2년차마다 나눠서 신청하는 지원금 제도. 직원별로 지금 어느 단계까지 신청했는지, 서류가 정상 접수됐는지, 기관에서 수정하라는 메일이 왔는지, 입금이 됐는지를 사장님이 계속 헷갈려함(신청 건이 여러 직원 × 여러 단계로 겹쳐서 진행됨). 이걸 표 하나로 정리해서 "지금 뭘 기다리고 있고, 뭘 고쳐야 하는지"를 한눈에 보이게 만든다.

기존 bonnoel-ops(매장 운영 앱)에 이미 사장님 로그인·Supabase 데이터 창고·서류 파일 저장(문서 업로드) 기능이 있으므로, 새 앱을 따로 만들지 않고 이 앱의 메뉴 하나로 추가한다.

## 화면
- 홈 화면에 **"청년지원금"** 아이콘 추가 (사장님 로그인일 때만 보임). 아이콘 위 숫자: 이번 달 예정일이 있는 건수 + 수정요청 진행중인 건수(급한 것 먼저 보이게).
- `#/subsidy` **목록 화면**: 직원 카드가 쭉 나열됨. 카드 안에 5단계(참여자등록 · 6개월 · 9개월 · 12개월 · 2년차) 배지가 순서대로 보이고, 배지 색으로 상태 표시(대기중=회색, 제출함=파랑, 수정요청=빨강, 접수완료=초록, 입금완료=진한 초록). 다음 예정일까지 D-day 표시. 상단에 기관(잡모아/메이크인) 탭, 상태 필터(진행중만 보기 등).
  - 위 [직원 등록] 버튼 → 이름 · 기관(25 잡모아 / 26 메이크인) · 채용일 · 매장 입력 → 저장하면 5단계 건이 자동 생성됨(예정일은 채용일 기준 자동 계산, 나중에 직접 고칠 수 있음).
- **건 상세 화면** (카드의 배지를 누르면 열림):
  - 필요서류 체크리스트(예: 참여자등록 단계는 서식1~4). 각 항목마다 파일 올리기(사진/PDF) + 체크. 체크리스트 항목은 직접 추가·삭제 가능(기관마다 요구서류가 다를 수 있으니 고정하지 않음).
  - 상태 바꾸기 버튼(대기중→제출함→수정요청→접수완료→입금완료, 순서 상관없이 자유롭게 변경 가능 — 기관이 접수완료 후에 다시 수정요청을 보낼 수도 있으므로).
  - 진행 기록(타임라인): 날짜순으로 메모 + 파일 추가. 여기에 "기관에서 수정요청 메일 옴 — 내용: ...", "전화로 확인, 3일 뒤 재제출 예정" 같은 걸 계속 쌓아서, 맨 위 최신 기록만 봐도 "지금 뭘 기다리는 중인지" 알 수 있게 함.
  - 입금액 · 입금일 입력칸(예상 금액은 기본값을 넣어두되 직접 고칠 수 있음: 6개월=180만원, 9개월·12개월=90만원, 2년차는 빈칸).
- 직원이 퇴사하면 카드에서 [퇴사 처리] → 아직 안 지난 단계는 "중단" 배지로 바뀌고, 왜 중단인지 메모를 남기게 함(예: "8개월차 퇴사, 9개월 신청 불가").

## 규칙
- 이 메뉴는 사장님 로그인에서만 보임(매니저·직원 화면에는 노출 안 함).
- 5단계 예정일 계산: 채용일 + 6개월 / +9개월 / +12개월 / +24개월. 참여자등록 예정일은 채용일과 동일(등록은 보통 채용 직후 진행).
- 채용일을 나중에 고치면 "예정일도 다시 계산할까요?" 확인 후 아직 완료되지 않은 단계만 다시 계산(이미 접수완료·입금완료된 단계는 건드리지 않음).
- 파일은 기존 "입사 서류"와 같은 `documents` 저장소를 재사용하되 `subsidy/` 폴더 아래에 저장해서 구분함.
- 주민등록번호 등 민감정보는 이 메뉴에서 새로 저장하지 않음(서식 안에 있는 정보는 업로드하는 파일 안에만 있고, 앱 표에는 이름·기관·채용일·매장·상태·메모만 저장).

## 데이터 (Supabase)
새 표 3개, `supabase-migration-subsidy.sql`로 관리:

- `ops_subsidy_employees` — 참여 직원. `id, name, agency(jobmoa25/makein26), hire_on, store, active, created_at`
- `ops_subsidy_cases` — 단계별 신청 건. `id, employee_id(FK), stage(register/m6/m9/m12/y2), due_on, status(waiting/submitted/revision/accepted/paid/stopped), checklist(jsonb: [{name, done, file_path}]), amount, paid_on, stopped_reason, created_at, updated_at`
- `ops_subsidy_logs` — 진행 기록 타임라인. `id, case_id(FK), content, file_path, created_at`

기존 모듈과 동일하게 RLS는 "anon full access"(앱 로그인으로만 구분, DB 단에서는 열어둠), 파일은 기존 `documents` 버킷 재사용.

## 나중에
- 기관 메일함을 앱이 직접 읽어서 수정요청을 자동으로 기록하는 건 지금 범위 밖(이메일 연동은 별도 설정이 많이 필요함) — 지금은 사장님이 메일 받으면 진행 기록에 직접 붙여넣는 방식.
- 지원금 금액 규정이 바뀌면(예: 2년차 금액 확정) 건 상세 화면에서 직접 수정하면 되고, 코드에 금액을 고정해두지 않음.
