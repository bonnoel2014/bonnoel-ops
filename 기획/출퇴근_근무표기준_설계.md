# 출퇴근 근무표 기준 처리 + 추가 근무 승인 (12차) 설계

## 왜
지금 출퇴근은 버튼 누른 시각을 1분 단위로 그대로 인정 시간에 씀(`recNet` = 실제 − 휴게). 그래서 5분 일찍/3분 늦게 누른 것까지 급여에 섞여 애매하고, 매번 사장님이 "이건 인정? 아님?"을 판단해야 함.
→ **인정 시간은 근무표가 정한다.** 출퇴근 버튼은 "왔다/갔다" 확인용. 근무표보다 더 일한 시간은 **직원이 사유와 함께 올리고 사장님이 수락해야만** 인정.

전제: 근무표(그 주 전용 표 / 고정 패턴 + 휴무·대타)가 정확해야 함. 근무표가 곧 급여 기준이 됨.

## 흐름
### 출근 (매장폰 `#/clock`)
1. 이름 + 비밀번호 → [출근하기]
2. 앱이 오늘 이 사람의 근무표 칸을 찾음(`shiftsOn`, 대타로 들어간 칸 포함). 하루에 칸이 둘 이상이면 지금 시각에 가장 가까운 칸.
3. 기록에 **근무표 시작·끝·휴게**를 복사해 저장 + 실제 누른 시각도 참고로 저장.
4. 화면: "출근 처리됐어요. 오늘 근무 10:00~18:00 (휴게 1시간) · 인정 7시간"
5. 일찍 눌렀든 늦게 눌렀든 **아무 안내도 하지 않음**. 직원 화면에는 근무표 시간만 보이고, 실제 누른 시각·"몇 분 일찍" 같은 표시는 보여주지 않음.

### 퇴근
1. [퇴근하기] → 근무표 끝 시각으로 퇴근 처리(실제 누른 시각은 참고로 저장).
2. 늦게 눌러도 **아무 안내 없음**(출근과 같음).
3. 퇴근을 깜빡해도 인정 시간은 근무표대로 잡힘. 근무 조회에 "퇴근 안 누름" 표시만.

### 추가 근무 올리기 (직원)
- **원칙: 앱이 먼저 권하지 않는다.** "조기 출근 올릴까요?" 같은 멘트를 띄우면 1~2분도 올려야 하나 싶어져 일이 커짐(사장님 결정 9/23). 본인이 떳떳하다고 생각할 때만 스스로 쓰는 칸.
- 위치: 매장폰 출퇴근 화면(이름+비밀번호 뒤) 아래쪽에 작은 [추가 근무 올리기] 칸, 내 폰 메뉴에도 같은 칸. 출근·퇴근 버튼과 떨어뜨려 눈에 덜 띄게.
- 종류: **조기 출근** / **연장(늦게 끝남)** / 기타
- 입력: 실제 시작 시각(조기) 또는 실제 퇴근 시각(연장) → 추가 시간 자동 계산(수정 가능, 10분 단위), **사유(필수)**
- 올리면 상태 "승인 대기". 매장폰 이름표에 "추가 근무 대기" 작게 표시.
- 당일 못 올렸으면 자기 폰(로그인)에서 **3일 이내** 올릴 수 있음.

### 승인 (사장님, `#/extra-approve`)
- 홈 "출퇴근·근무" 칸에 대기 건수 배지.
- 목록: 날짜 · 이름 · 매장 · 종류 · 근무표 시간 · 실제 누른 시각 · 올린 추가 시간 · 사유
- 버튼: **수락** / **시간 고쳐서 수락**(예: 40분 올렸는데 30분만) / **거절**(사유 한 줄)
- 수락된 것만 인정 시간·급여에 들어감. 거절되면 직원 폰에서 거절 사유 보임.

## 규칙
- **인정 시간 = (근무표 끝 − 근무표 시작 − 근무표 휴게) + 수락된 추가 근무**
- 야간(22~06)도 근무표 구간 + 수락된 추가 구간 기준으로 계산.
- 수락된 추가 근무는 급여의 연장 계산(하루 8h·주 40h 초과 가산)에 그대로 들어감.
- 실제 누른 시각은 **지우지 않고 보관**(분쟁·노동청 대비 증거). 근무 조회에서 "실제 기록" 열로 보임.
- 근무표가 바뀌면(출근 후 사장님이 근무표를 고친 경우) 그 날 기록의 근무표 복사본을 다시 맞출지 근무 조회에서 [근무표로 다시 맞추기] 버튼 제공.
- 전환일: `ops_settings` key `attendance_mode` = `{ mode: 'schedule', since: 'YYYY-MM-DD' }`. 전환일 전 기록은 지금처럼 실제 시각 기준으로 계산(지난달 급여가 갑자기 바뀌지 않게).

## 결정이 필요한 부분 (기본값 = ★)
1. **지각했을 때** — ★ 근무표대로 인정하되 근무 조회에 "지각 12분" 빨간 표시(사장님이 필요하면 직접 차감) / 늦은 만큼 자동 차감 / 무시
2. **일찍 퇴근했을 때** — ★ 근무표대로 인정 + "조기 퇴근 25분" 표시 / 자동 차감
3. **근무표에 없는 날 출근** — ★ 출근은 되고 인정 0, "오늘 근무표에 없어요" 사실만 표시(직원이 필요하면 추가 근무 칸에 직접 올림)(전체를 사장님이 수락) / 출근 자체를 막기
4. **승인권자** — ★ 사장님만 / 사장님 + 매니저
5. **추가 근무 단위** — ★ 10분 / 30분 / 1분

## 법적으로 알아둘 점 (노무사 확인 권장)
- 근무표 기준 인정 자체는 가능. 다만 사장님(또는 매니저)이 **시켰거나 알면서 두었던** 초과 근무는 승인 버튼을 안 눌렀어도 임금 지급 의무가 생길 수 있음.
- 그래서 실제 기록은 반드시 보관하고, 근무 조회에 **"실제 기록이 근무표보다 30분 이상 긴데 추가 근무를 안 올린 날"** 목록을 따로 보여줌 → 사장님이 놓친 건 없는지 한 번 훑어볼 수 있게.
- 5인 이상 사업장이라 연장·야간 가산은 기존 급여 규칙대로.

## 데이터
- `ops_attendance` 열 추가: `sched_start time`, `sched_end time`, `sched_break_min int`, `no_schedule boolean default false` (clock_in/clock_out은 실제 누른 시각으로 그대로 사용)
- 새 테이블 `ops_attendance_extras`: id, attendance_id(null 가능: 근무표 없는 날), staff_id, branch_id, work_date, kind(early/late/other), start_at, end_at, minutes, reason, status(requested/approved/rejected), approved_minutes, decided_by, decided_at, reject_reason, created_at. RLS는 다른 테이블과 같이 anon 전체 허용.
- 마이그레이션 파일: `supabase-migration-extras.sql` (멱등, 사장님 실행)

## 바꾸는 곳 (코드)
- `clockIn` / `clockOut`: 근무표 칸 찾아 sched_* 저장, 조기/연장 제안 화면
- `recNet`: 전환일 이후 기록은 근무표 기준 + 수락된 추가분. **근무 조회와 급여 초안 둘 다 이 함수를 쓰므로 여기만 바꾸면 급여까지 따라감.**
- `#/hours`: 열 = 근무표 / 실제 기록 / 추가(수락·대기) / 인정, 지각·조기퇴근·퇴근 안 누름 표시, "안 올린 초과 의심" 목록
- 새 화면: 추가 근무 올리기(매장폰·내 폰), `#/extra-approve`(사장님), 내 추가 근무 내역
- 홈 배지
