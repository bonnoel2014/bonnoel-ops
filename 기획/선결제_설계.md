# 선결제 (2026-09-24 설계, 사장님 승인)

## 목적
월 3만원 유료 선불권 앱을 운영 앱 안의 무료 기능으로 대체. 참고: gayoungene-prepay.vercel.app (신청서만 받고 잔액은 POS에 있음 → 우리는 잔액 장부까지 직접 가짐).

## 규칙
- 충전: 매장에서 카드·현금으로 받고 직원이 기록. 한 번에 **10만원 이상이면 5% 추가 적립** (예: 10만 → 105,000). 기준·비율은 사장님이 앱에서 바꿀 수 있음(prepay_settings).
- 사용: 4매장 공용 잔액. 계산대에서 번호 뒷자리 → 직원이 이름 확인 → 금액 빼기. 잔액 넘게 못 씀.
- 손님 1명 = 휴대폰 번호 1개 (단체는 대표 번호).
- 잘못 입력: 기록은 지우지 않고 "취소" 줄을 새로 남김. 매장 코드로는 **오늘 우리 매장 기록만** 취소, 사장님 코드는 전부.
- 환불(사장님만): **추가 적립분을 빼고** 환불. 환불 가능액 = 잔액 − (지금까지 받은 적립 합계), 0 미만이면 0. 환불하면 잔액·적립 합계 모두 0으로.
- 기존 앱 잔액 옮기기(사장님만): 엑셀 붙여넣기(번호·이름·잔액). 옮긴 잔액은 적립분 구분이 없어 전액 "낸 돈"으로 봄.

## 보안 (돈이라서 운영 앱보다 세게)
- 운영 앱의 manual_staff.pin 은 평문이고 누구나 읽을 수 있음 → 선결제엔 못 씀.
- 대신 **매장별 코드(6자리) + 사장님 코드(6자리)**, pgcrypto bcrypt 로 암호화 저장.
- prepay_* 표는 RLS 켜고 정책 없음 → 앱에서 직접 읽기·쓰기 불가. 모든 동작은 security definer 함수(코드를 서버에서 확인)로만.
- 코드 20번 틀리면 5분 잠금. 손님 조회 비밀번호(4자리)는 5번 틀리면 10분 잠금.
- 사장님 코드는 SQL 실행 직후 사장님이 앱에서 처음 정함(비어 있을 때만 가능).
- 기록마다 매장·직원 이름(서버가 manual_staff에서 찾아 씀)·시각.

## 화면
- `#/prepay` (모두): 코드 입력 → 번호 검색 → 손님 → [사용]/[충전]. 새 손님 충전. 오늘 우리 매장 기록 + 취소.
- `#/prepay-c/<id>`: 손님 잔액·내역, 사용·충전, 손님 비밀번호 정하기, (사장님) 환불.
- `#/prepay-admin` (사장님): 기간·매장별 합계(받은 돈/적립/사용/환불, 매장별 하루 충전 합계 → POS와 대조), 손님 목록·남은 잔액 합계, 옮기기, 코드·적립 규칙 설정.
- `prepay.html` (손님용, 직원 메뉴 없음): 이용안내 + 번호·비밀번호 4자리로 잔액·내역.

## 사장님이 할 일
1. Supabase SQL Editor 에 `supabase-migration-prepay.sql` 붙여넣고 실행
2. 앱 선결제 화면에서 사장님 코드 정하기 → 4매장 코드 정하기
3. 기존 앱에서 손님 목록 엑셀 → 붙여넣기
4. 몇 주 기존 앱과 같이 쓰며 숫자 대조 후 유료 해지
