## 흐름
1. **서류 준비** (사장님·매니저, `#/docs-admin`): 직원 고르기 → 근무지·계약기간·수습·담당업무·시급(급여 설정에서 자동)·급여일·식대·요일별 근무시간(근무 패턴에서 자동)·유니폼 품목 → 저장 → 그 직원 앞으로 서류가 "서명 대기"로 걸림
2. **서명** (신입, 매장폰 `#/sign`, 로그인 없이): 매장 → 내 이름 → 비밀번호 4자리 → 본인 정보(생년월일·연락처·주소·이메일) 입력 → 서류를 한 장씩 끝까지 읽고 동의 항목 체크 → 손가락 서명(한 번 그리면 다음 서류에도 적용) → 만 18세 미만이면 친권자 동의서가 추가됨(친권자가 같이 있으면 그 자리에서 서명, 없으면 서명 없이 첨부해 종이로 받음)
3. **완료**: 폰에서 PDF를 만들어 저장소(`documents` 버킷)에 올리고, 서버 함수 `send-document`가 직원 메일 + 사장님 메일(참조)로 PDF를 첨부해 보냄. 화면에 "○○@○○로 보냈어요"
4. **다시 보기**: 직원은 로그인 후 `내 서류`에서 열람·저장. 사장님·매니저는 서류 관리에서 직원별 상태(없음/대기/서명됨/발송 완료/발송 실패)·재발송·PDF 보기
5. **출근 화면**: 서명 안 끝난 사람은 "입사 서류를 아직 안 썼어요" 안내. 홈(매니저)에 "서류 미완료 ○명"

## 증거로 남기는 것 (ops_documents 한 줄 = 서류 한 장)
- 서명 이미지(저장소), 서명 시각, 사용 기기(user agent), 접속 IP(서버 함수가 기록), 양식 버전
- PDF 파일 경로 + SHA-256 지문 (나중에 파일이 바뀌지 않았음을 증명)
- 보낸 메일 주소(직원·참조), 보낸 시각, 실패 시 오류 내용

## 데이터 (supabase-migration-docs.sql)
- `ops_documents`: batch_id(한 번에 준비한 묶음), staff_id, branch_id, doc_key(contract/privacy/pledge/cctv/uniform/guardian), doc_title, template_version, data(jsonb: 계약 조건+본인 정보+체크), status(prepared/signed/sent/failed), signature_path, pdf_path, pdf_sha256, signed_at, signed_ua, signed_ip, email_to, email_cc, email_sent_at, email_error, prepared_by
- `ops_settings` key `docs`: { owner_email, seal(직인 이미지 data URL) }
- 저장소 버킷 `documents` (비공개, 서명 URL로 봄). 경로 `{staff_id}/{batch_id}/{doc_key}.pdf`, `signature.png`

## 메일 발송 (supabase/functions/send-document)
- 앱이 `{ batch_id, ua }`를 보내면 함수가 그 묶음의 PDF를 저장소에서 내려받아 한 통으로 보냄. 받는 사람 = 직원이 입력한 이메일, 참조 = 사장님 메일
- 보내는 계정: bonnoel.news@gmail.com (지메일 앱 비밀번호는 함수 비밀값 GMAIL_USER / GMAIL_APP_PASSWORD). 함수가 배포 안 됐거나 실패하면 상태가 "발송 실패"로 남고 서류 관리에서 재발송
- 대안: 지메일 SMTP가 막히면 MAIL_PROVIDER=resend + RESEND_API_KEY + MAIL_FROM(도메인 인증 필요)
