# 기획안(PRD) — 리뷰 뽑기판 (디지털 뽑기) · v2

> 초안 — v1을 써 본 뒤 고칩니다

- 가게 / 이름: 본노엘 / 손성필
- 주제(영역): 손님 응대 · 리뷰 이벤트 운영
- 이 버전의 목표 한 줄: 사장님이 이벤트로 나간 빵을 돈으로 보고, 1등 충전금과 일일 보고서가 뽑기 기록과 자동으로 이어지는 도구

## 1. 무엇을 왜 만들고 싶나요?

v1으로 뽑기와 기록은 되지만, "이벤트에 한 달 얼마가 드는지"는 아직 사장님이 머릿속으로 곱해야 한다. 1등 충전금은 직원이 선결제 쪽에서 따로 적립해야 하고, 일일 보고서에도 뽑기 숫자가 빠져 있다.

## 2. 누가 언제 쓰나요?

- 사장님: 월말에 비용 보기. 상품 단가 입력.
- 매장 매니저: 오늘 품절인 등수 끄기.
- 직원: 1등 충전금 자동 적립 때 확인 버튼.

## 3. 지금은 어떻게 하고 있나요?

(v1 사용 뒤 `v1/사용메모.md`를 보고 채움)

## 4. 도구를 쓰면 어떤 일이 달라지나요?

사장님 현황에 금액 줄이 생기고, 1등이 나오면 결과 화면에서 "충전금 적립" 확인 한 번으로 선결제에 들어가며, 일일 보고서에 "오늘 뽑기 N번" 한 줄이 자동으로 붙는다.

## 5. 이번 버전에서 만들 것

**꼭 할 것**
- 이벤트 비용 환산: 상품별 단가(원가 또는 판매가) 입력 → 사장님 현황에 매장별 월 비용 표시.
- 1등 선결제 충전금 자동 적립: 성수·중계·답십리 1등 결과 화면에 "충전금 30,000 적립" 버튼 → 직원이 손님 번호 확인 후 누르면 선결제 모듈에 적립. 준비물: 선결제 DB 함수에 "이벤트 적립" 사유 추가, 적립 기록이 뽑기 기록과 연결.

**여유 있으면**
- 품절 등수 잠그기: 매니저가 오늘 품절 등수를 끄면 그 칸이 나와도 다음 등수 상품을 안내하고 기록에 남김.
- 일일 보고서 합계: 기존 일일 보고서에 "오늘 뽑기 N번 · 1등 N" 한 줄.
- 리뷰 출처 기록: 뽑기 시작 때 네이버/카카오맵/구글 선택, 현황에 채널별 수.

**이번에 하지 않을 것:** 손님 폰 QR 뽑기 · 리뷰 삭제 감시 (나중)

## 6. 완성됐다는 걸 어떻게 확인하나요?

- 시연할 예시 입력: 단가 5개 입력 후 성수점 10월 집계 보기 · 성수점 1등 뽑힘 → 충전금 적립 버튼.
- 기대하는 결과: 성수 10월 비용 금액이 표시됨 · 선결제 쪽에 "이벤트 적립 30,000"이 기록되고 뽑기 기록에도 "적립 완료" 표시.
- 잘못 입력했을 때: 단가 비면 그 상품은 "단가 없음"으로 금액 제외 · 적립 버튼 두 번 눌러도 한 번만.
- 다시 열었을 때 남아 있어야 할 것: 단가표, 적립 연결 기록, 품절 설정.

## 7. 다음 버전에서 더할 것

- 손님 폰 QR 뽑기(중복 참여 막는 방법 정한 뒤) · 리뷰 삭제 감시(자동으로 읽을 방법 찾은 뒤).

## 8. 절대 자동화하면 안 되는 것

- 충전금 적립은 직원 확인 버튼 없이 자동으로 들어가지 않는다.
- 상품 단가·상품표 변경은 사장님(·매니저)만.
