# 명부 동기화 (9차) 설계

## 왜
사장님이 근무자 현황 구글 시트를 매번 열어서 신입·퇴사·보건증을 손으로 하나씩 처리하기 번거로움. "시트를 통째로 붙여넣으면 앱이 알아서 정리해 줬으면 좋겠다"는 요청. 다만 시트가 로그인 잠금(401)이라 Claude가 스스로 주기적으로 열어서 동기화할 수는 없음 → 사장님이 붙여넣을 때마다 한 번에 처리하는 방식으로 구현.

## 화면
- `#/roster-sync` (사장님·매니저): 붙여넣기 칸 하나. 시트에서 머리글 줄(지점·이름·입사일·보건증 만료일·퇴사일)까지 같이 복사하면 각 칸을 정확히 찾아 읽음. 붙여넣으면 자동으로 4묶음 미리보기:
  - **신입으로 추가**: 앱에 없는 이름. 체크박스로 추가 여부 선택(기본 켜짐).
  - **퇴사 처리 제안**: 이미 있는 사람인데 퇴사일 칸에 진짜 날짜가 있음. 체크박스로 처리 여부 선택(기본 켜짐).
  - **확인 필요**: 퇴사일 칸에 글자는 있는데 날짜가 아님(예: "왕십리이동"). 자동 처리 안 하고 사람이 직원·비밀번호에서 직접 판단하도록 안내만.
  - **보건증 만료일 갱신**: 시트 날짜가 앱보다 최신인 사람.
- "이대로 저장" 한 번으로 위 항목을 한꺼번에 처리.
- 기존 "보건증 관리"의 시트 붙여넣기 칸은 이 화면으로 통합·이전(중복 제거). 보건증 관리에는 이 화면으로 가는 링크만 남음.

## 규칙
- 주민번호·주소·전화·이메일은 어디에도 저장하지 않음(붙여넣은 원본 텍스트 자체도 저장 안 함 — 화면에서 파싱 후 각 필드만 메모리에 잠깐 유지).
- 저장하는 값: 지점, 이름, 입사일(`manual_staff.hire_on`, 기존 값이 없을 때만 채움), 보건증 만료일(`ops_health_certs`, 앱 기록보다 최신일 때만), 퇴사 여부(`manual_staff.active=false` + `memo`에 "퇴사 YYYY-MM-DD (명부 동기화)" 기록, 기존 메모에 이어붙임).
- 퇴사 자동 판단은 (1) 날짜처럼 보이는 값(`27.07.03`, `2027.3.19` 등), (2) 날짜는 없지만 "퇴사"·"퇴직"이라는 글자만 있는 값(예: 그냥 "퇴사") 두 경우에만 적용. (2)는 저장할 때 정확한 날짜 없이 "날짜 미상"으로 메모에 남김. 그 외 텍스트(예: "왕십리이동")는 절대 자동으로 퇴사 처리하지 않음 — 지점 이동, 오타, 메모 등 사람 손을 타야 하는 경우가 섞여 있기 때문(예: 강수민·김성연 사례처럼 실제로는 지점 이동이었음).
- 이름 매칭: 같은 지점 우선, 없으면 전체 소속(실장 등), 그 다음 아무나 일치. 동명이인이 다른 지점에 있으면 "앱에는 ○○점" 경고를 보여줌(보건증 화면과 동일한 로직 재사용: `hcMatchStaff`, `hcParseDate`, `hcBranchByName`).

## 데이터
- `manual_staff.hire_on` (date, nullable) 추가 — `supabase-migration-roster.sql`.
- 새 테이블 없음. 보건증은 기존 `ops_health_certs`, 퇴사는 기존 `manual_staff.active`/`memo` 재사용.

## 나중에
- 시트를 서비스 계정에 공유해 진짜 자동 폴링을 하려면: 시트 소유자가 "링크가 있는 모든 사용자에게 보기 권한" 또는 서비스 계정 이메일에 공유 필요(지금은 401이라 불가). 지금은 "사장님이 붙여넣을 때마다"가 최선.
